# Архитектура проекта

## Общее описание

Проект представляет собой современное Angular приложение с модульной архитектурой, использующее современные практики разработки и лучшие подходы для создания масштабируемых веб-приложений.

## Структура проекта

```
src/
├── app/
│   ├── app.component.ts          # Корневой компонент приложения
│   ├── app.config.ts             # Конфигурация приложения
│   ├── app.routes.ts             # Определение маршрутов
│   ├── core/                     # Центральная часть приложения
│   │   ├── interceptors/         # Перехватчики HTTP запросов
│   │   ├── layout/               # Компоненты отображения
│   │   ├── routing/              # Стратегии маршрутизации
│   │   └── services/             # Сервисы ядра
│   ├── features/                 # Функциональные модули
│   └── shared/                   # Общие компоненты
├── environments/                 # Конфигурации окружений
└── assets/                       # Статические ресурсы
```

## Основные компоненты

### 1. app/
Корневая директория приложения с основными файлами:
- `app.component.ts` - корневой компонент, отвечающий за отображение маршрутов
- `app.config.ts` - конфигурация Angular приложения
- `app.routes.ts` - определение маршрутов приложения

### 2. core/
Центральная часть приложения с ядром функциональности:
- **interceptors/** - перехватчики HTTP запросов (авторизация, обработка ошибок, загрузка)
- **layout/** - компоненты отображения (шапка, подвал, меню и т.д.)
- **routing/** - стратегии маршрутизации
- **services/** - сервисы ядра приложения

### 3. features/
Функциональные модули приложения:
- Содержит логически связанные компоненты и функциональность
- Каждый модуль может быть независимо разработан и протестирован

### 4. shared/
Общие компоненты и утилиты:
- Повторно используемые компоненты
- Общие сервисы и утилиты
- Компоненты UI библиотеки

## Архитектурные паттерны

### 1. Модульная архитектура
Проект разделен на модули для обеспечения:
- Четкого разделения ответственности
- Легкости поддержки и масштабирования
- Возможности независимой разработки модулей

### 2. Dependency Injection
Используется Angular DI для управления зависимостями:
- Сервисы предоставляются через провайдеры
- Простое тестирование и замена реализаций

### 3. Интерцепторы HTTP
Все HTTP запросы проходят через перехватчики:
- `authInterceptor` - обработка авторизации
- `errorInterceptor` - обработка ошибок
- `loadingInterceptor` - отображение состояния загрузки

## Конфигурация приложения

Файл `app.config.ts` определяет основные провайдеры приложения:
- `provideZoneChangeDetection` - управление детекцией изменений
- `provideRouter` - маршрутизация с настройками
- `provideAnimations` - анимации
- `provideHttpClient` - HTTP клиент с перехватчиками

## Стратегии маршрутизации

Файл `shell-route-reuse.strategy.ts` реализует стратегию повторного использования маршрутов:
- Оптимизация производительности при навигации
- Сохранение состояния компонентов при переходах

## Основные принципы разработки

1. **Масштабируемость** - архитектура позволяет легко добавлять новые функции
2. **Поддержка** - четкое разделение ответственности облегчает сопровождение
3. **Тестируемость** - модульная структура и DI упрощают тестирование
4. **Производительность** - оптимизация через стратегии повторного использования маршрутов

## Рекомендации по разработке

1. Все новые компоненты создавать в соответствующих модулях
2. Использовать сервисы ядра для общего функционала
3. При добавлении новых функций создавать новые модули в features/
4. Общие компоненты размещать в shared/
5. Все HTTP запросы проходят через перехватчики
